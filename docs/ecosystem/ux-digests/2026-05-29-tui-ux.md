## Executive summary

- **No production Li TUI** in org repos; harness audits **fixtures only** (`tui-app-fixture`, `tui-gen-fixture` in `li-cursor-agents/config/ux-targets.json`).
- **`tui-app-fixture` fails** both UI and UX audits: `read -r` blocks non-interactive harness → `subprocess.TimeoutExpired` after 30s ([#30](https://github.com/li-langverse/li-cursor-agents/issues/30)); piped stdin (`h`/`q` as lines) exits 0 in &lt;50ms.
- **`run_audit.py` uncaught timeout:** harness crashes with stack trace instead of recording a fail row — fix alongside #30.
- **`tui-gen-fixture` passes** (static box frame) but **journeys empty** — `cli_to_tui` never executed; rubric scores are defaults, not journey evidence ([#33](https://github.com/li-langverse/li-cursor-agents/issues/33)).
- **Error + a11y export gap:** fixtures lack `LI_TUI_ERROR=1` failure branch and `LI_TUI_EXPORT_A11Y` structured plain snapshot ([#34](https://github.com/li-langverse/li-cursor-agents/issues/34)).
- Global `data/latest/ux-audit.json` preflight remains **docs-only** (`lic-docs`); TUI targets require proactive harness invocation under `data/latest-tui-*-run/`.
- **SOTA (manifest `tui`):** [Textual](https://textual.textualize.io/) (BINDINGS footer, `Ctrl+P` command palette, `ModalScreen` help); [Bubble Tea](https://github.com/charmbracelet/bubbletea) (vim+arrow nav, `q`/`ctrl+c` quit, errors via model not panic).
- **Vision-LLM posture:** `lic diagnose` and `lic check --format=json` are **JSON-first** today — future Li TUI is presentation over proved diagnostics, not a parallel error channel.
- **Deferred:** production `lic`/`lis` TUI, VHS/PTY baselines, stdlib Textual/Bubble Tea bindings until terminal stack lands.

### Flow audit — focus areas

#### Key navigation

| Area | Fixture | SOTA | Gap |
|------|---------|------|-----|
| Focus / roving keys | Mock text only | Textual `set_focus`, footer BINDINGS | No widget focus model |

| Journey `key_nav_help` | Defined, **not run** | Textual Pilot `press("h")` | [#33](https://github.com/li-langverse/li-cursor-agents/issues/33) |

#### Help overlays

- `tui-demo.sh` prints help only after **two** `read` lines; banner says `h` for help but key is not interpreted.
- Textual: `ModalScreen` + `push_screen` / `pop_screen` ([screens guide](https://textual.textualize.io/guide/screens/)); command palette `Ctrl+P` ([command palette](https://textual.textualize.io/guide/command_palette/)).
- Bubble Tea: help as dedicated view state; quit always available via `tea.Quit`.

#### Error display

- `tui-gen-fixture`: always `Status: ok` — no failure path.
- `tui-app-fixture`: no `LI_TUI_ERROR=1` branch.
- Bubble Tea: return error `tea.Msg` to `Update`, render in `View` ([error handling](https://deepwiki.com/charmbracelet/bubbletea/5.2-error-handling-and-recovery)).
- [#34](https://github.com/li-langverse/li-cursor-agents/issues/34).

#### Screen reader / plain-text export

- No `LI_TUI_EXPORT_A11Y=1` artifact; ANSI clear (`\033[2J`) without semantic structure.
- Textual: widget labels + accessibility themes ([Real Python overview](https://realpython.com/python-textual/)).
- Li should adopt **structured plain export** (headings, lists — not layout spaces) for agent ingestion alongside human TUI.
- [#34](https://github.com/li-langverse/li-cursor-agents/issues/34).

### Li ecosystem posture

- **Vision-LLM** ships `lic check --format=json` and `lic diagnose` (JSON stdout) — terminal UX for agents is **JSON-first**, not interactive TUI today ([spec](https://github.com/li-langverse/lic/blob/main/docs/superpowers/specs/2026-05-16-li-llm-first-design.md)).
- **Proof-before-perf:** future `li-tui` / generator must not use `unsafe` or unproved shortcuts; TUI is presentation layer over proved diagnostics.
- **Harness gap:** `adapters/tui.py` hardcodes `error_handling: 0.75` on pass — not derived from journeys or missing states.
