#### Help overlays

- `tui-demo.sh` prints help only after **two** `read` lines; `h` key not interpreted.
- Textual: modal `Screen` + `push_screen` / command palette ([guide](https://textual.textualize.io/guide/screens/), [command palette](https://github.com/Textualize/textual/blob/main/docs/guide/command_palette.md)).
- Bubble Tea: help as dedicated `View` state or Bubbles component — errors stay in model `View`, not stderr-only.

#### Error display

- `tui-gen-fixture`: always `Status: ok` — no failure path.
- `tui-app-fixture`: no `LI_TUI_ERROR=1` branch.
- Bubble Tea pattern: return error `tea.Msg` to `Update`, render in `View` ([error handling](https://deepwiki.com/charmbracelet/bubbletea/5.2-error-handling-and-recovery)).
- [#34](https://github.com/li-langverse/li-cursor-agents/issues/34).

#### Screen reader / plain-text export

- No `LI_TUI_EXPORT_A11Y=1` artifact; ANSI clear (`\033[2J`) without semantic structure.
- Textual: widget labels + accessibility themes ([Real Python overview](https://realpython.com/python-textual/)).
- Li should adopt **structured plain export** (headings, lists — not layout spaces) per [WCAG plain-text techniques](https://www.w3.org/TR/WCAG20-TECHS/text.html) for agent ingestion alongside human TUI.
- [#34](https://github.com/li-langverse/li-cursor-agents/issues/34).
