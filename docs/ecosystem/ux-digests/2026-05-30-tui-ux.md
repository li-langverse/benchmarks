## Executive summary

- **No production Li TUI** in org repos; audits cover **harness fixtures** only (`tui-app-fixture`, `tui-gen-fixture` in `li-cursor-agents/config/ux-targets.yaml`).
- **`tui-app-fixture` fails** UI and UX: `read -r` blocks non-interactive harness → `subprocess.TimeoutExpired` after 30s; piped stdin (`h`/`q` as lines) exits 0 in &lt;50ms — tracked in [li-cursor-agents#30](https://github.com/li-langverse/li-cursor-agents/issues/30).
- **`run_audit.py --all` crashes** on TUI timeout (uncaught `TimeoutExpired`) instead of recording a fail row — fix alongside #30.
- **`tui-gen-fixture` passes** (static box frame) but **journeys empty** — `cli_to_tui` never executed; rubric scores are adapter defaults, not journey evidence ([#33](https://github.com/li-langverse/li-cursor-agents/issues/33)).
- **Error + a11y export gap:** fixtures lack `LI_TUI_ERROR=1` failure branch and `LI_TUI_EXPORT_A11Y` structured plain snapshot ([#34](https://github.com/li-langverse/li-cursor-agents/issues/34)).
- Global `data/latest/ux-audit.json` preflight remains **docs-only** (`lic-docs`); TUI targets require proactive harness invocation under `data/latest-tui-*-run/`.
- **SOTA (manifest `tui`):** [Textual](https://textual.textualize.io/) (BINDINGS footer, `Ctrl+P` command palette, `ModalScreen` help); [Bubble Tea](https://github.com/charmbracelet/bubbletea) (vim+arrow nav, `q`/`ctrl+c` quit, errors via model not panic).
- **Vision-LLM posture:** `lic diagnose` and `lic check --format=json` are **JSON-first** today — future Li TUI is presentation over proved diagnostics, not a parallel error channel.

### Flow audit — focus areas

#### Key navigation

| Area | Fixture | SOTA | Gap |
|------|---------|------|-----|
| Focus / roving keys | Mock text only | Textual `set_focus`, footer BINDINGS ([widgets guide](https://textual.textualize.io/guide/widgets/)) | No widget focus model |
| Vim bindings | N/A | Bubble Tea `up`/`k`, `down`/`j`, `q`/`ctrl+c` ([input handling](https://charmbracelet-bubbletea-43.mintlify.app/guides/input-handling)) | Not demonstrated |
| Journey `key_nav_help` | Defined, **not run** | Textual Pilot `press("h")` ([Pilot API](https://textual.textualize.io/api/pilot/)) | [#33](https://github.com/li-langverse/li-cursor-agents/issues/33) |

#### Help overlays

- `tui-demo.sh` prints help only after **two** `read` lines; banner says `h` for help but key is not interpreted.
- Textual: stack-based help via `push_screen` / `ModalScreen` ([screens guide](https://textual.textualize.io/guide/screens/)); command palette `Ctrl+P` ([command palette](https://textual.textualize.io/guide/command_palette/)).
- Bubble Tea: help as dedicated view state; quit always available via `tea.Quit`.

#### Error display

- `tui-gen-fixture`: always `Status: ok` — no failure path.
- `tui-app-fixture`: no `LI_TUI_ERROR=1` branch.
- Bubble Tea: store error on model, return `tea.Quit`, surface in `main` after `Run` — not panic in `View`.
- [#34](https://github.com/li-langverse/li-cursor-agents/issues/34).

#### Screen reader / plain-text export

- No `LI_TUI_EXPORT_A11Y=1` artifact; ANSI clear (`\033[2J`) without semantic structure.
- Textual: semantic widgets (`Label`, `Button`), focus management, screen-reader-oriented themes ([Real Python overview](https://realpython.com/python-textual/)).
- Li should adopt **structured plain export** (headings, lists — not layout spaces) for agent ingestion alongside human TUI.
- [#34](https://github.com/li-langverse/li-cursor-agents/issues/34).

### Li ecosystem posture

- **Vision-LLM** ships `lic check --format=json` and `lic diagnose` (JSON stdout) — terminal UX for agents is **JSON-first**, not interactive TUI today ([llm-first spec](https://github.com/li-langverse/lic/blob/main/docs/superpowers/specs/2026-05-16-li-llm-first-design.md)).
- **Proof-before-perf:** future `li-tui` / generator must not use `unsafe` or unproved shortcuts; TUI is presentation layer over proved diagnostics.
- **Harness gap:** `adapters/tui.py` hardcodes `error_handling: 0.75` on pass — not derived from journeys or `missing_states`.
