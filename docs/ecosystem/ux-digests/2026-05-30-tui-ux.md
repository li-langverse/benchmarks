#### Help overlays

- `tui-demo.sh` prints help only after **two** `read` lines; banner says `h` for help but key is not interpreted.
- Textual: Footer widget auto-displays BINDINGS ([Footer guide](https://textual.textualize.io/widgets/footer/)); extended help via `ModalScreen` + `push_screen` ([binding API](https://textual.textualize.io/api/binding/)).
- Bubble Tea: help as dedicated view state; quit always available via `tea.Quit` ([input handling guide](https://www.mintlify.com/charmbracelet/bubbletea/guides/input-handling)).

#### Error display

- `tui-gen-fixture`: always `Status: ok` — no failure path.
- `tui-app-fixture`: no `LI_TUI_ERROR=1` branch.
- Bubble Tea: store error on model, inspect after `p.Run()` — do not panic on recoverable failures ([#1279](https://github.com/charmbracelet/bubbletea/issues/1279)).
- [#34](https://github.com/li-langverse/li-cursor-agents/issues/34).

#### Screen reader / plain-text export

- No `LI_TUI_EXPORT_A11Y=1` artifact; ANSI clear (`\033[2J`) without semantic structure.
- Textual: widget labels + binding tooltips in Footer ([binding API](https://textual.textualize.io/api/binding/)).
- Li should adopt **structured plain export** (headings, lists — not layout spaces) for agent ingestion alongside human TUI.
