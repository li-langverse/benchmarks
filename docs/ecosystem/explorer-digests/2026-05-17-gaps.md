## Web spot-check → Li gap

**PETSc + Kokkos (PDE stack):** Exascale practice treats Kokkos as the vendor-neutral GPU portability layer inside PETSc (KSP/SNES/DM, batched preconditioners, matrix solvers on device). **Li gap:** tier-2 physics still leans on shared C cores and has no implicit solver / AMG / distributed mesh story; Phase **7d** decorators are policy-only without memory-space lowering — years behind a minimal PETSc+Kokkos-shaped stack.

**Stdlib numerics / SIMD (2025 languages):** Rust (SVE/SME, SIMD multiversioning) and Go (`GOEXPERIMENT=simd`) are investing in portable vector APIs and multi-target codegen. **Li gap:** Phase **7e** documents “not started” for full math lowering; red `horner_pure_li` is the measurable symptom — need planned SIMD/poly eval lowering, not catalog threshold tweaks.

**Kokkos vs OpenMP portability:** Studies show both can work on CPUs/GPUs; Kokkos tends to cover more vendor backends, while OpenMP-target can lag on hierarchical GPU parallelism. **Li gap:** no first-class parallel loop surface mapped to LLVM/OpenMP or Kokkos-like policies; **7d** must connect `std/execution/decorators.li` to real codegen.

**FFTW / roofline:** Vendor FFT (e.g. MKL) often beats FFTW; parallel 3D FFT is communication-bound. **Li gap:** explorer correctly flags **no FFT catalog row** — cannot claim signal/HPC parity until `fft_micro` + `std/signal` (or documented vendor hook) exists.
