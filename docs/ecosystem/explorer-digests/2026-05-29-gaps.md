### C. Web spot-check (2026-05-29)

**PETSc + Kokkos PDE stack.** PETSc 3.25+ treats Kokkos as a first-class GPU backend: single-source solver configuration, `VecGetKokkosView` for device-resident data, and `PCBJKOKKOS` for batched device preconditioners ([PETSc GPU roadmap](https://petsc.org/release/overview/gpu_roadmap/), [PCBJKOKKOS](https://petsc.gitlab.io/petsc/main/manualpages/PC/PCBJKOKKOS/)). **Li gap:** tier-2 physics and PDE catalog rows remain **unknown** or **shared_c_kernel**; no KSP/SNES/DM story — route to **sim** research + **lic#117** / **lic#108**, not lic monolith codegen without `plan-approved`.

**Stdlib numerics / SIMD roadmaps.** NumPy NEPS prioritize portable SIMD (Highway, SVE); C++ `std::simd` is entering the working draft; Java Vector API (JEP 508) and Go `GOEXPERIMENT=simd` show industry move to **predictable vector abstractions** over ad-hoc intrinsics. **Li gap:** matrix `@` and blocked GEMM still partial (**2i**, **7e**); near-green micros must not overclaim in handbook until **G-math** rows close in same PR — **lic#27**, **lic#33**.

**Kokkos vs OpenMP portability (HPC expectation).** Exascale teams standardize on Kokkos as vendor-neutral portability with Kokkos-Kernels wrapping vendor BLAS ([ALCF PETSc+Kokkos](https://www.alcf.anl.gov/news/optimizing-petsc-exascale)). **Li gap:** `std/execution/decorators.li` is policy without memory spaces or GPU backends — **lic#15**, registry competitor rows for Kokkos-class execution.

**FFTW / vendor FFT roofline.** Community benchmarks treat vendor FFT (cuFFT, MKL) vs FFTW as a roofline crossover problem. **Li gap:** `fft_1d_fixed` is green on recent matrix; tier catalog still benefits from explicit roofline row — **benchmarks#18**, **#26**, **#52** (existing).
