### C. Web spot-check (2026-05-29)

**PETSc + Kokkos (PDE stack):** Exascale PETSc work treats Kokkos as the primary portability layer with shared execution spaces (`PetscGetKokkosExecutionSpace`) and COO-style GPU assembly — industry expects **unified device views + solver stack**, not ad-hoc C kernels per vendor. Remaining production pain includes vector-op kernel-launch overhead, MPI_Allreduce in norms, and Kokkos-Kernels gaps on some backends. **Li gap:** tier-2 physics still uses **shared C cores** and stub packages; no proved implicit solver / AMG path — handoff to **sim** + **lic#117** after PH-7d execution spaces exist.

**Stdlib numerics / SIMD (2025–2026):** C++26 is standardizing portable `std::simd` data-parallel types; Go 1.26 ships `simd/archsimd` under `GOEXPERIMENT=simd` with a planned high-level portable API. **Li gap:** PH-2i partial 1d surface + PH-7e codegen without a portable rank-N mdspan-class API or closed **G-math** for loop matmul ≡ reference — **numerics_researcher** + **lic#27**.

**Kokkos vs OpenMP portability:** Plasma-physics portability studies (2024–2025) show Kokkos delivers broader vendor coverage; OpenMP GPU offload often reaches only ~30–70% of native CUDA/HIP and is highly sensitive to directive/compiler choices — Kokkos-OMPX / OpenMP 6.1 aim to close the gap. **Li gap:** `std.execution.decorators` is OpenMP-adjacent syntax without Kokkos-class **memory spaces** or policy objects — **lic#15**, **lic#109**.

**FFTW / roofline:** FFT performance crosses compute-bound (small N, cache-resident) to memory-bound (large N) per inverse-roofline curves; FFTW and vendor MKL/cuFFT set the reference bar with run-time planner selection. **Li gap:** no tier-1 FFT micro-bench with roofline reference — **benchmarks#18**, **benchmarks#52**; defer pure-Li FFT until **G-math** plan exists.
