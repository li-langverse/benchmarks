### C. Web spot-check (2026-05-29)

**PETSc + Kokkos PDE stack.** PETSc 3.25 ships production Kokkos backends for vectors/matrices (`VecGetKokkosView`, `MatCreateSeqAIJKokkosWithKokkosViews`) with GPU roadmap work on residual/Jacobian assembly and `PCBJKOKKOS` solvers; users share execution spaces via `PetscGetKokkosExecutionSpace` for stream coherency. **Li gap:** no KSP/SNES/AMG or distributed-mesh story; tier-2 physics uses shared C cores and extern stubs — **lic#117**, **lic#14**, **lic#15**.

**Stdlib numerics / SIMD roadmaps.** C++26 `std::simd` (P1928) is landing in GCC 16 libstdc++ (x86-first); Go 1.26 adds `simd/archsimd` intrinsics as foundation for a portable vector API. Languages treat explicit, predictable SIMD GEMM as baseline, not optional auto-vectorization. **Li gap:** matrix `@`, blocked matmul, and ML kernels still above 1.2× tier-1 gate despite closed horner slice — **PH-2i**, **PH-7e**, **lic#27**, **lic#33**.

**Kokkos vs OpenMP portability.** 2024–2026 studies (plasma physics, IWOMP 2025) report Kokkos delivers broader out-of-box portability across Intel/AMD/NVIDIA fleets; OpenMP target backends remain sensitive to construct choice and lambdas (4–8× regressions on some ROCm paths). LLVM OpenMP extensions close gaps to ~91–95% of native on newer GPUs. **Li gap:** `std.execution.decorators` is policy-only (no memory spaces, no backend selection) — **lic#15**, **lic#109**; aligns with **G-par** partial row.

**FFTW / vendor FFT roofline.** Community benchmarks compare FFTW, cuFFT, VkFFT for crossover sizing; FFTs are memory-bound on GPUs with roofline analysis standard. **Li gap:** no tier-1 FFT catalog row — **benchmarks#18**, **#52**, **#26**.
