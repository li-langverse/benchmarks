### C. Web spot-check (2026-05-29)

**PETSc + Kokkos (PDE stack):** PETSc 3.25 treats Kokkos as a first-class GPU backend (`MATAIJKOKKOS`, `VECKOKKOS`, `PCBJKOKKOS` batched Jacobi on device) with zero-copy `VecGetKokkosView` / `VecRestoreKokkosView` and device-side assembly via Kokkos-Kernels sparse routines. Production stacks expect unified device assembly, solver hierarchies on-device, and careful sync avoidance — GPU solves can still underperform CPU when host-device copies dominate. **Li gap:** tier-2 physics still uses **shared C cores** and stub packages; no proved implicit solver / AMG path — handoff to **sim** + **lic#117** after PH-7d execution spaces exist.

**Stdlib numerics / SIMD (2025–2026):** C++26 standardizes portable `std::simd` (`std::datapar::basic_simd`, GCC libstdc++ landing x86-first); Go 1.26 ships `simd/archsimd` under `GOEXPERIMENT=simd` with a planned high-level portable API; Java continues Vector API incubation. **Li gap:** PH-2i partial 1d surface + PH-7e codegen without a portable rank-N mdspan-class API or closed **G-math** for loop matmul ≡ reference — **numerics_researcher** + **lic#27**.

**Kokkos vs OpenMP portability:** Plasma-physics and leadership-facility studies (2024–2025) show Kokkos delivers broader vendor coverage (often ~78–91% of native CUDA/HIP on complex kernels); OpenMP GPU offload often reaches only ~30–70% of native backends and is highly sensitive to directive/compiler choices — though Kokkos-OMPX + LLVM extensions are closing gaps. **Li gap:** `std.execution.decorators` is OpenMP-adjacent syntax without Kokkos-class **memory spaces** or policy objects — **lic#15**, **lic#109**.

**FFTW / roofline:** FFT performance crosses compute-bound (small N) to memory-bound (large N); FFTW and vendor MKL/cuFFT set the reference bar with run-time planner selection. **Li gap:** no tier-1 FFT micro-bench with roofline reference — **benchmarks#18**, **benchmarks#52**; defer pure-Li FFT until **G-math** plan exists.
