### C. Web spot-check (2026-05-31)

**PETSc + Kokkos PDE stack.** PETSc 3.25 exposes device-resident vectors (`VecGetKokkosView`), `aijkokkos` matrices, and batched preconditioners (`PCBJKOKKOS`); production stacks select matrix/vector types at runtime without rewriting application APIs, with `-log_view` to catch host/device transfer bottlenecks. **Li gap:** tier-2 physics catalog and `li-physics-*` packages remain scaffold-level — no KSP/SNES/DM story, no device view ABI — **lic#14**, registry `gap-hpc-petsc-kokkos-implicit-pde`.

**Stdlib numerics / SIMD roadmaps.** C++26 `std::simd`, Go `simd/archsimd`, and mature compiler auto-vectorization dominate 2025–2026 discourse; production GEMM still relies on cache tiling + vendor BLAS or hand-tuned intrinsics. **Li gap:** PH-2i/7e partial — `matmul_blocked` still >1.2× while Horner is green; needs decorator→MIR codegen proof, not catalog threshold tweaks — **lic#27**, **lic#33**.

**Kokkos vs OpenMP portability.** ICS 2025 and plasma PIC studies show Kokkos P≈0.91 across vendors while prescriptive OpenMP GPU backends often reach 30–70% of native CUDA/HIP; Kokkos-OMPX extensions target OpenMP 6.1 (fall 2026). **Li gap:** `std/execution/decorators.li` has no execution spaces, views, or backend tags — **lic#15**, **lic#109**.

**FFTW vs vendor FFT roofline.** CPU FFTW leads at small N; GPU cuFFT/VkFFT cross near 2^16; roofline separates memory-bound small transforms from compute-bound batched FFTs. **Li gap:** `fft_1d_fixed` near 1.01× but no tier-1 pure-Li FFT proof row or vendor crossover harness — **benchmarks#18**, **benchmarks#26**, **benchmarks#52**.
