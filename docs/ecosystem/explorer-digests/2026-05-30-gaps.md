### C. Web spot-check (2026-05-30)

**PETSc + Kokkos PDE stack.** PETSc 3.25+ integrates Kokkos/Kokkos-Kernels for GPU-resident algebra; production stacks still hit backend-specific gaps (e.g. Jacobi diagonal on device without `MATAIJKOKKOS`). Hybrid apps often mix Kokkos user kernels with PETSc solvers on a shared execution space/stream. **Li gap:** no KSP/SNES/DM/time-integrator story; tier-2 relies on shared C cores and physics scaffolds — **lic#14**, **lic#15**, sim loop `sim-p2-qm-dft-scf`.

**Stdlib numerics / SIMD roadmaps.** NumPy (NEP-54 Highway, SVE/RVV), Go 1.26 `GOEXPERIMENT=simd`, and Java Vector API (JEP 508) all treat portable SIMD + predictable GEMM as baseline infrastructure. **Li gap:** PH-2i matrix `@` and PH-7e lowering still drive **matmul** / ML reds (~1.33–1.55×); near-threshold greens need sustained **numerics_research**, not catalog threshold tweaks — **lic#27**.

**Kokkos vs OpenMP portability.** ICS 2025 and plasma studies show Kokkos/RAJA often match or beat native CUDA/HIP on multi-vendor GPUs; OpenMP GPU backends remain sensitive to directive/compiler choices (P ≈ 0.45–0.79 in recent studies). **Li gap:** `std.execution.decorators` is policy AST, not memory spaces + portable kernels — **lic#15**.

**Horner / tier-1 regression.** Prior cycle’s **~88×** `horner_pure_li` regression is **absent** from the current red set; remaining reds are modest matmul/ML/GMRES ratios — focus shifts to blocked SIMD matmul and registry ML kernels.
