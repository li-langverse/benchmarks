**PETSc + Kokkos PDE stack.** Production stacks use `aijkokkos` matrices, Kokkos views via `DMDAVecGetKokkosOffsetView`, shared execution spaces via `PetscGetKokkosExecutionSpace`, and device COO assembly (`MatSetValuesCOO`) rather than host `MatSetValues`. **Stdlib numerics / SIMD roadmaps.** C++26 `std::simd` (P1928) and Go 1.26 `simd/archsimd` raise the bar for portable vector GEMM and reductions; GCC libstdc++ implementation is x86-first with math/permute still open. **Li gap:** PH-2i matrix `@` and PH-7e SIMD matmul still partial; six red tier-1 rows block PH-5b claim — **lic#27**, **lic#33**, registry `gap-benchmark-red-*`.

**Kokkos vs OpenMP portability.** 2024–2026 studies show Kokkos achieving broader hardware coverage than prescriptive OpenMP on plasma/PIC codes, though OpenMP remains competitive on CPU-only paths; OpenMP GPU backends are sensitive to construct choice (30–70% of native Kokkos/HIP in worst cases). **Li gap:** decorators are policy AST without execution spaces, views, or backend selection — **lic#15**, **lic#109**.
