### C. Web spot-check (2026-05-30)

**PETSc + Kokkos PDE stack.** PETSc 3.25 integrates Kokkos for device-resident vectors (`VecGetKokkosView`), `aijkokkos` matrices, and batched preconditioners (`PCBJKOKKOS`); production stacks select matrix/vector types at runtime (`-dm_mat_type aijkokkos -dm_vec_type kokkos`) without rewriting application APIs. **Li gap:** tier-2 physics catalog and `li-physics-*` packages remain scaffold-level — no KSP/SNES/DM story, no device view ABI — **lic#14**, **lic#117**.

**Stdlib numerics / SIMD roadmaps.** C++26 `std::simd`, Go `simd/archsimd`, Java Vector API, and NumPy 2.0 Highway SIMD all push portable vector layers; hot-path practice still favors compiler auto-vectorization or hand-tuned kernels (Ferray, MKL). **Li gap:** PH-2i/7e partial — matmul still >1.2× C++ while Horner is green; needs decorator→MIR codegen proof, not catalog threshold tweaks — **lic#27**, **lic#33**.

**Kokkos vs OpenMP portability.** Plasma PIC and Kokkos-OpenMP target studies show Kokkos near-native on H100/MI300A (P≈0.91) while OpenMP GPU backends often reach 30–70% of CUDA/HIP and vary sharply by compiler/directive. **Li gap:** `std/execution/decorators.li` has no execution spaces, views, or backend tags — **lic#15**, **lic#109**.

**FFTW vs vendor FFT roofline.** CPU FFTW leads at small N; GPU cuFFT/VkFFT cross over near 2^16; roofline separates memory-bound small transforms from compute-bound batched FFTs. **Li gap:** `num_fft_r2c` catalog path audit-only; no tier-1 pure-Li FFT proof row — **benchmarks#18**, **benchmarks#26**, **benchmarks#52**.
