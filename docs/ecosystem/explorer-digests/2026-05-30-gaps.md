### C. Web spot-check (2026-05-30)

**PETSc + Kokkos PDE stack.** PETSc 3.25 integrates Kokkos Core/Kernels for GPU-resident algebra; production stacks use `VecGetKokkosView`, `DMDAVecGetKokkosOffsetViewDOF`, and device-native preconditioners like `PCBJKOKKOS` (batched block Jacobi in Kokkos thread groups). Hybrid apps mix Kokkos user kernels with PETSc solvers on shared execution spaces. **Li gap:** no KSP/SNES/DM/time-integrator story; tier-2 relies on shared C cores and physics scaffolds — **lic#14**, **lic#15**, sim loop `sim-p2-qm-dft-scf`.

**Stdlib numerics / SIMD roadmaps.** Go 1.26 ships `simd/archsimd` under `GOEXPERIMENT=simd` with a two-level strategy (arch-specific intrinsics → portable high-level API); C++26 `std::simd` and Java Vector API continue parallel work. Ecosystems treat portable SIMD + predictable GEMM as baseline infrastructure. **Li gap:** PH-2i matrix `@` and PH-7e lowering still drive **matmul** / ML reds (~1.33–1.55×); near-threshold greens need sustained **numerics_research**, not catalog threshold tweaks — **lic#27**.

**Kokkos vs OpenMP portability.** 2024–2025 studies (plasma PIC, ACM ICS proxy apps) show Kokkos/RAJA often match or beat native CUDA/HIP on complex kernels; OpenMP GPU offloading is sensitive to compiler/construct choices (sometimes 30–70% of native, worst ~30× slower). Kokkos wins broader hardware coverage; OpenMP offers lower porting barrier but inconsistent perf. **Li gap:** `std.execution.decorators` is policy AST, not memory spaces + portable kernels — **lic#15**.

**Eigen / constexpr GEMM.** Expression-template and compile-time matmul techniques remain the Eigen/MKL baseline. Li tier-1 matmul reds suggest blocked SIMD codegen gap, not missing catalog rows — focus **bench_improver** on `matmul_blocked` (1.55×) first.
