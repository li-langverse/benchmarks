### C. Web spot-check (2026-05-30)

**PETSc + Kokkos PDE stack.** PETSc 3.25 exposes Kokkos Views on vectors/matrices (`VecGetKokkosView`, `MatSeqAIJKokkos`) and device-native preconditioners like `PCBJKOKKOS` for block Jacobi on GPU thread groups — production PDE stacks keep data device-resident with explicit sync/restore pairs. **Li gap:** no KSP/SNES/DM/time-integrator surface; tier-2 physics uses shared C cores and scaffold packages — lic [#117](https://github.com/li-langverse/lic/issues/117), [#14](https://github.com/li-langverse/lic/issues/14).

**Stdlib numerics / SIMD roadmaps.** C++26 ships `std::simd` (P1928) and Go 1.26 adds `simd/archsimd` under `GOEXPERIMENT=simd`, both layering portable vector APIs atop architecture-specific intrinsics; community consensus favors language-level or compiler auto-vectorization over library-only abstractions for hot loops. **Li gap:** PH-2i/7e partial — six tier-1 reds (matmul/ML/GMRES at 1.33–1.55× C++) despite horner green; needs decorator→MIR codegen, not catalog threshold tweaks — lic [#27](https://github.com/li-langverse/lic/issues/27), [#33](https://github.com/li-langverse/lic/issues/33).

**Kokkos vs OpenMP portability.** Plasma PIC and LLNL Kokkos-OMPX work show Kokkos tracks native CUDA/HIP within ~90% on H100/MI300A while OpenMP target backends often reach only 30–70% of native and are sensitive to directive/compiler choices; Kokkos v5 targets C++20 with compile-time backend selection. **Li gap:** `std/execution/decorators.li` has no execution spaces, views, or backend tags — lic [#15](https://github.com/li-langverse/lic/issues/15), [#109](https://github.com/li-langverse/lic/issues/109).

**FFTW vs vendor FFT roofline.** CPU FFTW wins below ~64 KiB–1 MiB; GPU cuFFT crosses over near 2^16 elements; roofline turns compute-bound → memory-bound. **Li gap:** no tier-1 FFT catalog row (`num_fft_r2c` path audit-only); benchmarks [#18](https://github.com/li-langverse/benchmarks/issues/18), [#26](https://github.com/li-langverse/benchmarks/issues/26), [#52](https://github.com/li-langverse/benchmarks/issues/52).
