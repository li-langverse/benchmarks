### C. Web spot-check (2026-05-30)

**PETSc + Kokkos PDE stack.** PETSc v3.25 ships Kokkos/Kokkos-Kernels backends (`-dm_mat_type aijkokkos`, device-resident assembly, PCBJKOKKOS batched Jacobi); exascale apps (e.g. LAMMPS-Kokkos) expect GPU-resident loops with minimal host↔device copies. **Li gap:** no KSP/SNES/DM/time-integrator surface; tier-2 physics uses shared C cores and scaffold `li-physics-*` packages — lic [#117](https://github.com/li-langverse/lic/issues/117), [#14](https://github.com/li-langverse/lic/issues/14).

**Stdlib numerics / SIMD roadmaps.** C++26 `std::simd` (P1928) and Go 1.26 `simd/archsimd` (low-level intrinsics; portable `simd` API proposed) normalize layered SIMD in stdlib; production HPC still leans on intrinsics/EVE until std implementations mature. **Li gap:** PH-2i/7e partial — six tier-1 reds (matmul 1.33–1.55×, ML kernels, `num_gmres` 1.40×) need codegen not catalog tweaks — lic [#27](https://github.com/li-langverse/lic/issues/27), [#33](https://github.com/li-langverse/lic/issues/33).

**Kokkos vs OpenMP portability.** ICS 2025 proxy-app study: Kokkos ~parity with native CUDA/HIP on many cases; OpenMP target often 30–70% of native and sensitive to directive/compiler pairs. **Li gap:** `std/execution/decorators.li` has no execution spaces, views, or backend selection — lic [#15](https://github.com/li-langverse/lic/issues/15), [#109](https://github.com/li-langverse/lic/issues/109).

**FFTW vs vendor FFT roofline.** Gearshifft-style studies: CPU FFTW leads below ~1 MiB input; cuFFT crosses near 2^16 elements; post-crossover regime is memory-bound on roofline. **Li gap:** `num_fft_r2c` catalog path is audit-only (harness in benchmarks repo); no proven `pure_li` FFT — benchmarks [#18](https://github.com/li-langverse/benchmarks/issues/18), [#26](https://github.com/li-langverse/benchmarks/issues/26), [#52](https://github.com/li-langverse/benchmarks/issues/52).
